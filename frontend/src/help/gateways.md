## Summary

An edge gateway is what actually talks to machines and publishes their data to the broker. Every device in this stack arrives underneath one. This page is where gateways are created, enrolled, watched and taken out of service. A gateway is a Sparkplug edge node, not a level of the ISA-95 hierarchy: the standard names the devices behind it and the places they stand in. A gateway serves a cell, a whole area (**Area-Wide**) or the whole site (**Site-Wide**), so that the devices reporting through it can inherit that location. A Simulated gateway serves none of these: its devices land in the Simulated lane instead.

## What the controls do

- **The banners** above the card are the page's unfinished business, and there are up to three: devices assigned to no gateway; gateways that should be reporting and are not; and, only for someone who can create gateways, that this deployment cannot enrol a Remote gateway yet, with the address to fix. The Gateways icon in the sidebar turns amber while a gateway is offline; the second banner is where that colour is explained. A gateway still awaiting setup is not offline, and nor is the Playback gateway between playbacks.
- **The list** opens on **Active**, so archived gateways are one filter away. It includes the **Playback gateway**, the one gateway every stack is seeded with, which publishes recorded captures from the Capture page. A new install lists only that one, with a line under it saying there are no other gateways yet.
- **The filters** narrow the list. The first select is the lifecycle, with how many gateways each option holds (Active, Archived, All); those numbers count the same rows the list shows. The search box matches the name, the UUID and the Sparkplug ID. **Any status** filters by Online, Stale or Offline. **Any type** filters by Remote, Host, Simulated or Playback. **Has quarantined devices** shows only gateways currently reporting devices held in quarantine, which points at a misconfigured edge node when several devices fail at once. **Clear filters** counts every control that is off its default and resets them all.
- **The columns** are the name (with an ARCHIVED badge when it is out of service), the UUID (click to copy), the Type, the Location, the status, the age of the last heartbeat, and the devices assigned to the gateway, collapsed past three with the Online and Offline summary always kept. While the drawer is open the UUID and devices columns step aside, since the drawer shows both, so the table fits beside it.
- **New Gateway** opens the **Register Gateway** dialog: a name, an optional description, the Type, the Location and an optional access URL for the gateway's own console. Nothing is installed from here. For a Remote gateway, saving opens **Set up** at once, since a Remote gateway does nothing until it is run on its machine.
- **Setting up a Remote gateway** issues a single-use token in one of two forms. Where the deployment can serve it, the default is an **install command** to paste on a fresh Ubuntu machine. Otherwise, or on request, it is a **bundle**: a ZIP to unpack and start with Docker. The drawer's **Set Up Gateway** action does the same for a gateway still awaiting setup, and **Re-issue Setup** for one that enrolled and never published. Issuing replaces any earlier token, so the dialog asks you to type the gateway's name first. A remote gateway's broker credential is issued to the appliance when it enrols and never passes through a browser, which is why there is nothing to copy down here and nothing that can be re-shown later.
- **Generate Broker Credential** is for Host and Simulated gateways, which have no appliance to enrol. It issues the gateway's broker account and shows the password once. Issuing again replaces the password and drops the connection of anything using the old one. The dialog says where the pair goes: for a Host or Simulated gateway, the Security tab of its broker node in the Node-RED editor, which keeps it across restarts; for the Playback gateway, `secrets.mqttPlaybackCredentials`, which is delivered automatically when it can be.
- **The drawer** opens on a click of a row. Its rows are the identifiers and topic path, the Location, the last heartbeat and, once the appliance has reported health, **CA Expires**, disk, memory, load, runtime uptime and the bundle version. Below those are the flow, repository and convergence rows described further down. Its actions are Request Rebirth, Set Up Gateway or Re-issue Setup, Generate Broker Credential, **Launch UI** (shown only when the gateway has an access URL, and opening its own console in a new tab), Edit Details (Propose a Change for someone who may only propose), View Audit Trail, Attached Links and Archive Gateway. An archived gateway offers **Restore Gateway** in place of Edit and Archive. One action is highlighted and listed first: setup while the gateway awaits it, otherwise Launch UI, otherwise Restore Gateway on an archived gateway, otherwise Edit Details. **Request Rebirth** stays disabled until the gateway has published, since before then there is no birth certificate to restate.
- **The Playback gateway's drawer** offers only what playback needs: its broker credential, which is highlighted because playback cannot run without it, the audit trail and links. It cannot be edited, archived or asked for a rebirth.
- **Devices assigned to this gateway** are listed in the drawer as links to the Devices page. It is the short route from "this gateway is quiet" to "and these six things went quiet with it".
- **Repository** is the drawer's panel for this gateway's own repository in the forge, where its flow lives and where a change to it is proposed: commit the `flows.json` exported from the appliance's Node-RED editor on a branch and open a pull request. **Nothing is deployed until an administrator approves it** and it is merged to `main`, which the appliance then pulls. Administrators and Shopfloor Managers sign into the forge with their dashboard identity; nobody else holds a login there, so nobody else sees the panel. Both may create further repositories in the `gateways` organisation, for a playbook a class of gateway is provisioned from; those are not protected the way a gateway's own repository is until a gateway enrols under that name. Each gateway repository also has a **wiki**, for what a person needs to know and the appliance never reads: where it is, what it is wired to, who to call, what changed. It is edited directly and not reviewed, so nothing the appliance deploys belongs there. Its **issues** are the gateway's incident log: every repository starts with an **Incident** template that asks what happened, when, what the appliance was running, and what should change. The drawer's **Committed** row is where `main` is, reported by the forge on every push, so a merge shows here at once and the appliance deploys it on its next tick. A repository may also carry a **`custom.yml`**, a playbook the appliance runs on itself after the platform's own, hourly, through this same pull request lane; that is how a bespoke adapter for machinery no standard node reaches gets installed. A gateway that needs one can be seeded from the example repository in the forge with **Use this template**, before it is commissioned.
- **The drawer's Platform and Custom rows** are the last convergence. **Platform** is the playbook version this appliance is actually on, so different tags across the fleet mean a rollout in progress. **Custom** is what this gateway's own playbook did: empty when it has none, and **failed** when its adapter is not running. That one is worth knowing about, because an adapter has no heartbeat of its own: the gateway keeps publishing and still reads ONLINE while its adapter is down, and this row is the only place that shows.
- **A Host or Simulated gateway has no repository.** Its connector runs in this stack's own Node-RED, and one instance can carry several of them, so a `flows.json` is that whole instance rather than one gateway's. Edit those in the Node-RED editor.

## What the states mean

The status is what the gateway last reported, except **STALE**, which is worked out when you look.

- **AWAITING SETUP** — created here; the install command or bundle has not been used on the appliance yet.
- **ENROLLED — NO DATA YET** (`AWAITING_BIRTH` on the wire) — enrolled and connected, but it has not announced itself.
- **ONLINE** — heartbeat current.
- **STALE** — the stored status still says online, but the last heartbeat is older than 90 seconds. It is true at the moment you read it, and never stored.
- **OFFLINE** — no heartbeat and not mid-enrolment, or the gateway announced its own death (NDEATH). This one is a fault.
- **PLAYING BACK** and **IDLE** — the Playback gateway's only two states. It publishes only while a capture plays, so it reads PLAYING BACK while its heartbeat is fresh and IDLE otherwise. Idle is its resting state, never a fault.
- **Archived** — out of service on purpose, and left out of the attention signal for that reason. Archiving is the revocation: the broker account is disabled, any unused setup token is burned, the appliance's deploy key is removed, and its repository in the forge is archived, read-only, with every branch, issue and wiki page kept. **Restoring** the gateway puts back the last two: the deploy key and the repository. It does not bring back the first two. The broker account stays disabled until a credential is issued again, and a burned token cannot come back, so a Remote gateway is set up again with a fresh one. Nothing here deletes a repository; that is done in the forge.

**Type** says where the gateway runs and how far to trust its numbers. **Remote** runs on its own hardware out on the plant network. **Host** is a connector inside this stack, with nothing to install and no appliance to enrol. **Simulated** is a Host gateway whose readings are generated rather than observed. **Playback** is the seeded gateway that republishes recorded captures, and is not something you create.

A certificate within 30 days of expiry is called out in the gateway's drawer, on the **CA Expires** row, which appears once the appliance has reported its health. That warning is the only notice before the appliance stops being able to connect.

The same row reads **holds an older root** when this appliance has not yet been given the root the platform is publishing. Each appliance picks it up at its next hourly convergence, so a gateway can sit there for an hour after a root is re-issued and nothing is wrong. One that stays there has not converged: look at the gateway's `appliance` branch in the forge for what it said about the last attempt.
