## What this page is for

A gateway is the computer that talks to your machines and sends their data to the broker. Every device in Aber arrives through one. This page is where you create gateways, set them up, watch them and take them out of service.

A gateway serves a cell, a whole area (**Area-Wide**) or the whole site (**Site-Wide**), and the devices reporting through it take that location. A Simulated gateway serves none of these: its devices go in the Simulated lane instead. In Sparkplug terms a gateway is an edge node. It is not a level of the ISA-95 hierarchy, which names the devices behind it and the places they stand in.

## What the controls do

- **The banners** above the card are the page's unfinished business. There are up to three: devices assigned to no gateway; gateways that should be reporting and are not; and, for someone who can create gateways, that this deployment cannot set up a Remote gateway yet, with the address to fix. The Gateways icon in the sidebar turns amber while a gateway is offline, and the second banner explains why. A gateway still waiting to be set up is not offline, and nor is the Playback gateway between playbacks.
- **The list** opens on **Active**, so archived gateways are one filter away. It includes the **Playback gateway**, which every install has, and which replays recordings made on the Capture page. A new install lists only that one, with a line saying there are no other gateways yet.
- **The filters** narrow the list. The first select is the lifecycle (Active, Archived, All), with how many gateways each option holds. The search box matches the name, the UUID and the Sparkplug ID. **Any status** filters by Online, Stale or Offline, and **Any type** by Remote, Host, Simulated or Playback. **Has quarantined devices** shows only gateways reporting devices held in quarantine, which points at a misconfigured gateway when several devices fail at once. **Clear filters** says how many controls are changed, and resets them all.
- **The columns** are the name (with an ARCHIVED badge when out of service), the UUID (click to copy), the Type, the Location, the status, how long since the last heartbeat, and the devices assigned to the gateway. Past three devices the list collapses, keeping the Online and Offline summary. While the drawer is open, the UUID and devices columns are hidden so the table fits beside it; the drawer shows both.
- **New Gateway** opens the **Register Gateway** dialog: a name, an optional description, the Type, the Location, and an optional address for the gateway's own console. Nothing is installed from here. For a Remote gateway, saving opens **Set up** straight away, because a Remote gateway does nothing until it runs on its machine.
- **Setting up a Remote gateway** issues a single-use token, in one of two forms. Where this deployment can serve it, the default is an **install command** to paste on a fresh Ubuntu machine. Otherwise, or if you ask, it is a **bundle**: a ZIP to unpack and start with Docker. The drawer's **Set Up Gateway** does the same for a gateway still waiting to be set up, and **Re-issue Setup** for one that enrolled and never published. Issuing replaces any earlier token, so the dialog asks you to type the gateway's name first. A Remote gateway gets its broker password when it enrols, and the password never passes through a browser, so there is nothing to copy down here and nothing to show again later.
- **Generate Broker Credential** is for Host and Simulated gateways, which have no computer of their own to enrol. It issues the gateway's broker account and shows the password. Issuing again replaces the password and disconnects anything still using the old one. The dialog says where the password goes: for a Host or Simulated gateway, the Security tab of its broker node in the Node-RED editor, which keeps it across restarts; for the Playback gateway, `secrets.mqttPlaybackCredentials`, which is delivered automatically when it can be.
- **Show Broker Credential** shows a Host or Simulated gateway's password again, for an Administrator who has lost it. Each showing is recorded in the Audit Trail. A credential issued before this was possible has no copy: issue a new one instead.
- **The drawer** opens when you click a row. It shows the identifiers and topic path, the Location and the last heartbeat. Once a Remote gateway has reported its health, it also shows **CA Expires**, disk, memory, load, uptime and the bundle version. Below those are the flow, repository and convergence rows described further down.
- **The drawer's actions** are Request Rebirth, Set Up Gateway or Re-issue Setup, Generate Broker Credential, **Launch UI** (only when the gateway has a console address; it opens in a new tab), Edit Details (Propose a Change if you may only propose), View Audit Trail, Attached Links and Archive Gateway. An archived gateway offers **Restore Gateway** in place of Edit and Archive. One action is highlighted and listed first: setup while the gateway waits for it, otherwise Launch UI, otherwise Restore Gateway on an archived gateway, otherwise Edit Details. **Request Rebirth** stays disabled until the gateway has published, because until then it has no birth certificate to repeat.
- **The Playback gateway's drawer** offers only what playback needs: its broker credential, highlighted because playback cannot run without it, the audit trail and links. It cannot be edited, archived or asked for a rebirth.
- **Devices assigned to this gateway** are listed in the drawer as links to the Devices page: the quick way from "this gateway is quiet" to "and these devices went quiet with it".
- **Repository** is the drawer's panel for this gateway's own repository in the forge. Its flow lives there, and a change to the flow is proposed there: commit the `flows.json` exported from the gateway's Node-RED editor on a branch, and open a pull request. **Nothing is deployed until an administrator approves it** and it is merged to `main`, which the gateway then fetches. The **Committed** row shows where `main` is. The forge reports every push, so a merge shows here at once, and the gateway deploys it on its next check. Administrators and Shopfloor Managers sign in to the forge with their dashboard account. Nobody else has a login there, so nobody else sees this panel.
- **The repository's wiki** is for what a person needs to know and the gateway never reads: where it is, what it is wired to, who to call, what changed. It is edited directly and not reviewed, so nothing the gateway deploys belongs there. **Its issues** are the gateway's incident log: every repository starts with an **Incident** template that asks what happened, when, what the gateway was running, and what should change.
- **A custom playbook**, **`custom.yml`**, can sit in a gateway's repository. The gateway runs it on itself, hourly, after the platform's own, and it is changed through the same pull requests. That is how an adapter for unusual machinery gets installed. A gateway that needs one can be started from the example repository in the forge with **Use this template**, before it is commissioned. Administrators and Shopfloor Managers may also create other repositories in the `gateways` organisation, for a playbook shared by a class of gateway. Those are not protected like a gateway's own repository until a gateway enrols under that name.
- **The Platform and Custom rows** in the drawer show the last convergence. **Platform** is the playbook version this gateway is actually on, so different versions across the fleet mean a rollout is in progress. **Custom** is what this gateway's own playbook did: empty when it has none, and **failed** when its adapter is not running. Watch for that one. An adapter has no heartbeat of its own, so the gateway keeps publishing and still reads ONLINE while its adapter is down; this row is the only place it shows.
- **A Host or Simulated gateway has no repository.** It runs in Aber's own Node-RED, and one Node-RED can carry several of them, so its `flows.json` belongs to the whole instance rather than one gateway. Edit those flows in the Node-RED editor.

## What the states mean

The status is what the gateway last reported, except **STALE**, which is worked out when you look.

- **AWAITING SETUP**: created here, and the install command or bundle has not been used yet.
- **ENROLLED — NO DATA YET** (`AWAITING_BIRTH` on the wire): enrolled and connected, but it has not announced itself.
- **ONLINE**: its heartbeat is current.
- **STALE**: the stored status still says online, but the last heartbeat is more than 90 seconds old. It is true at the moment you look, and never stored.
- **OFFLINE**: no heartbeat and not being set up, or the gateway announced its own shutdown (NDEATH). This one is a fault.
- **PLAYING BACK** and **IDLE**: the Playback gateway's only two states. It publishes only while a recording plays, so it reads PLAYING BACK while its heartbeat is fresh and IDLE otherwise. Idle is its resting state, never a fault.
- **Archived**: out of service on purpose, so it is left out of the warnings on this page and in the sidebar. Archiving revokes the gateway: its broker account is disabled, any unused setup token is cancelled, its deploy key is removed, and its repository in the forge is archived, read-only, with every branch, issue and wiki page kept. **Restoring** the gateway brings back the deploy key and the repository, but not the other two. The broker account stays disabled until a credential is issued again, and a cancelled token cannot come back, so a Remote gateway is set up again with a fresh one. Nothing here deletes a repository; that is done in the forge.

**Type** says where the gateway runs and how far to trust its numbers. **Remote** runs on its own computer out on the plant network. **Host** runs inside Aber, with nothing to install and nothing to enrol. **Simulated** is a Host gateway whose readings are generated rather than measured. **Playback** is the gateway every install has, which replays recordings; you do not create it.

The **CA Expires** row in the drawer warns when a gateway's certificate is within 30 days of expiry. It appears once the gateway has reported its health. That warning is the only notice before the gateway can no longer connect.

The same row reads **holds an older root** when the gateway has not yet received the root certificate Aber now publishes. Each gateway picks it up at its next hourly convergence, so one can show this for up to an hour after the root is re-issued, and nothing is wrong. One that stays there has not converged: its `appliance` branch in the forge says what happened on the last attempt.
