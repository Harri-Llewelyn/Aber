## What this page is for

This page is the catalog of metrics that every schema is built from. A metric is a name, a datatype and a meaning, and a schema is a selection of metrics. Most metrics are not invented here. They are taken from a published standard on the Vocabulary page. That page passes the entry straight to the Add Metric dialog, so you do not have to type the values. The **Derived** tab holds metrics that Aber computes from others, such as parts per hour. The **Uncatalogued** tab shows the metrics your devices publish that the catalog does not describe yet.

## What the controls do

- **Metric Catalog**, **Derived**, **Deprecated Metrics** and **Uncatalogued** are the four tabs of the page's one card. The open tab's table scrolls inside the card, and its header and group headings stay in view. The columns of Metric Catalog and Deprecated Metrics line up.
- **Add Metric**, at the right-hand end of the Metric Catalog tab's toolbar, opens a dialog that builds a name from its parts. You see the full name before you commit to it. Its parts are **Group** (the component the metric belongs to), **Instance** (optional), **Type** (from the selected standard's vocabulary) and **Sub Type** (optional, for MTConnect only).
- **Standard** decides which vocabulary the Type picker draws from. It is stored on the metric as its source. Changing it clears everything the previous vocabulary decided, because a leftover type would make a wrong claim to other systems.
- **Semantic ID** and **Reference Type** link a metric to a term somebody else also uses, so it is no longer local to Aber. The field suggests the id the metric's standard gives it, marked **suggested**. An MTConnect metric gets its data item type's id, which every metric of that type shares. An ISO 22400 or OPC UA entry brings its own id. An ASHRAE 223P concept brings none.
- The suggestion stays until you type or pick another id, and **Use suggested** puts it back. A Custom metric, or a custom MTConnect type, gets no suggestion, and leaving it blank is correct. An invented id would only repeat the name, and would hide the metric from the export's count of unmapped metrics.
- **Search vocabularies**, beside the field, finds a concept by name, standard or id. It searches MTConnect, ISO 22400 and OPC UA, and the IDTA Digital Nameplate's elements. It sets the id and its reference type together, so you choose a nameplate IRDI rather than typing it. You can still type any id.
- A metric carries one semantic id. So a concept from another standard replaces the one the metric's own standard gives it. The metric keeps its standard as its source, and a note under the field says where the id came from.
- **Units** and **Sparkplug Datatype** are filled in from a vocabulary entry where its standard states them. Otherwise you choose. MTConnect gives units to SAMPLE data items only.
- The datatype is how the value is encoded on the wire. Like the name, it cannot be changed once the metric exists: to change it, deprecate the metric and create a new one. ISO 22400 and OPC UA entries fill it in. A 223P concept names a thing rather than a reading, so it leaves the datatype to you. The metric cannot be added until you choose one.
- **ASHRAE 223P is a reference here.** A 223P concept names a piece of equipment, such as a temperature sensor, not its reading. So choosing one fills in the group and the type, but no semantic id. Type the reading's own id if you know it. For example, the QUDT quantity kind `http://qudt.org/vocab/quantitykind/Temperature` names a temperature.
- **Permitted Values** lists the only values a metric may report, separated by commas, such as `READY, ACTIVE, STOPPED`. Leave it blank for a metric that may report any value, which most do. It appears once a datatype is chosen.
- A numeric metric takes whole numbers only, such as the codes of a mode. A measurement such as a temperature gets a valid range instead, in the schema builder. A Boolean metric takes `true`, `false` or both.
- A schema built from the metric copies its permitted values. A device set to Enforce then drops any other value. The Devices page tags a device whose last value is outside the list **Out of vocabulary**.
- **Search** finds a known metric by name or UUID without opening every group, and opens the groups that match. A UUID is what a link, a log line or the Audit Trail's drawer gives you. The groups are collapsed by default, and a group's tooltip says how many metrics it holds.
- **Any standard**, beside the search, filters the catalog by its Standard column. Tick one or more standards to list only the metrics named from them. Tick **Local extension** to list the metrics this site defined itself.
- **Unmapped** lists only the metrics with no semantic id. An AAS export writes them without one, so they cannot fill a Digital Nameplate field. When an export finds some, its warning leads here: select the warning to open this page with Unmapped on. To map one, select its row and use **Edit**. A local extension may be unmapped on purpose, because no vocabulary names it.
- The search and the two filters combine: a metric is listed only when it matches all of them. The groups they match open. Each standard shows how many metrics it holds among those the search and Unmapped let through. The Unmapped button counts every metric on this tab. **Clear filters** resets the search and both filters.
- The Deprecated Metrics tab is not filtered. It always lists every deprecated metric.
- **Expand all** opens every group, and reads **Collapse all** while any is open. Collapse all also closes the groups a search or a filter opened, and keeps the search and the filters.
- **Semantic ID** in the table is cut short in the middle, so its end stays visible: the end is what tells two ids apart. Click it to copy the whole id.
- **Selecting a row**, on the Metric Catalog, Derived and Deprecated Metrics tabs, opens the metric's drawer. Click anywhere on the row, or press Enter on it. The drawer shows the name, the metric's UUID, standard, category, units, datatype, semantic id, description, permitted values and how many schemas model the metric. For a deprecated metric, it also shows the metric that replaced it. For a derived metric, it shows the kind, the definition and **Applies To** instead of the standard, the semantic id and the permitted values. **Applies To** names the devices that report all its inputs, such as **Press 1, Press 2 and 3 more, the devices that report Controller/PART_COUNT**. It says **No device yet** while none does.
- **A column's heading sorts the table** by that column, on every tab. The Metric Catalog sorts the metrics inside each group, and the groups keep their order. Click it again to reverse the order, and a third time to go back to the usual order. A status sorts the most serious first, and an empty cell always sorts last. The page's address keeps the order, so a link or a reload shows the table the same way.
- The drawer holds **Edit**, **Deprecate** and **Restore**. All three need the Administrator role. A derived metric's drawer has no Edit. **View Audit Trail** opens the Audit Trail on the metric's own history: when it was added, corrected, deprecated or restored, and by whom. It is offered to whoever may open the Audit Trail.
- **Edit**, in the drawer, corrects a metric's **Semantic ID** and **Reference Type**, and its **Permitted Values**. Nothing else can change. Use it to fix a mistyped id, or a mapping that has moved on. It offers the same suggestion and search as Add Metric, so a cleared id is one click from restored. Clearing the id leaves the metric unmapped.
- Edit's confirmation says how many schemas model the metric, because every AAS shell exported from them carries the new id. The edit is recorded in the Audit Trail.
- Editing the permitted values changes no published schema: each keeps the values it was published with. The next version of a schema that you save on the Schemas page takes the new ones.
- **Deprecate**, in the drawer of a catalog metric, takes it out of the schema builder. It can name the metric that replaces it. The confirmation says how many schemas model it.
- **Restore**, in the drawer of a metric on the Deprecated Metrics tab, is the way back. It offers the metric to schema authors again, and clears the replacement it named. It asks first, as Deprecate does. Both are recorded in the Audit Trail, under Metric catalog, with who made them.
- **Derived** lists the metrics Aber computes from others. Each row shows the name, the kind, the definition in words and the unit. A derived metric is not on the Metric Catalog tab, and no device publishes it. A reading a device publishes under its name is dropped, and the Audit Trail records it. [History](history.md#derived-metrics) draws it on every device that reports all its inputs, with a **Derived** tag.
- There are three kinds. A **counter rate** is how fast a counter grows, per hour. A **time in state** is the share of time a state metric spends in the states you choose, from 0 to 1. A **sum or difference** adds or subtracts two to eight numeric metrics.
- **Add Derived Metric**, at the right-hand end of the Derived tab's toolbar, opens a dialog. It needs the Administrator role, as Add Metric does. Choose the **Kind**, then its inputs from the list below it. The name is built from a **Group**, an optional **Instance** and a **Metric Name**, and you see the full name before you commit to it.
- The inputs come from the same list as the schema builder's. **Search** it, filter by **Standard**, and tick a metric. The search and the filter narrow the list, never what you have chosen. **Chosen**, under the list, shows what you have.
- The list offers only measured metrics that are not deprecated, so a derived metric cannot be built on another. A rate takes one numeric counter. A time in state takes one string or boolean metric, and the states that count. Choosing another metric replaces the first. Where the metric lists its permitted values, you tick them.
- A sum takes two to eight metrics, listed under **Chosen** in the order you picked them. Each is added unless you press **−** beside it. They must share one unit.
- **Units** and **Sparkplug Datatype** are shown, not chosen. A rate is the counter's unit per hour, or `COUNT/HOUR` for a counter with none. A time in state has none. A sum takes the unit its inputs share. A derived metric is always a Double.
- The dialog says why **Add Derived Metric** is greyed. An input may be missing, the inputs of a sum may have unlike units, or a state may be one the metric cannot report. A device may also declare the name. Choose another name then, because the device and Aber would put readings in one series.
- A derived metric has no semantic id, no standard and no permitted values. Its definition says where its value comes from.
- **A derived metric cannot be changed.** Neither can its definition, its name or its unit. To change one, add a new derived metric. Then deprecate the old one, and name the new one as its replacement. A deprecated derived metric moves to the Deprecated Metrics tab.
- **Uncatalogued** lists the metric names your devices declare that no catalog row has. A device declares its metrics in its birth certificate when it connects. The tab's label shows how many names there are, so **Uncatalogued (0)** means the catalog covers every device.
- Each row shows the name, how many devices declare it, and which ones. Select a device to open it on the Devices page. A device still waiting for approval is marked **quarantined**. A long list shows three devices: select **more** to see the rest.
- **Datatype** is how the devices' birth certificates encode the value. It shows "—" when no birth certificate gave the metric a value. **Last Declared** is the last time one of these devices changed the set of metrics it declares.
- **Catalogue** opens Add Metric with the name filled in and the standard set to Custom. It fills in the datatype too, when the devices agree on one the form offers. Otherwise, choose it yourself. Like Add Metric, it needs the Administrator role, and it is not shown without it.
- Keep the name exactly as the devices declare it. If you change it, a warning says that the devices do not publish the new name.
- **Catalogue** is greyed out for a name the catalog cannot hold, such as one with a space. Its tooltip says which characters to remove. Rename the metric on the device instead.
- **Search**, on the Uncatalogued tab, finds a metric by its name. It does not search device names.
- The list leaves out archived devices and replay lanes. It also leaves out Sparkplug's control metrics, such as `Device Control/Rebirth`, because they are commands rather than readings. A deprecated metric counts as catalogued.

## What the states mean

**A metric name cannot be changed.** The name is what the device publishes, so it reaches MQTT, TimescaleDB and Grafana. Renaming it would strand every reading already stored under the old name. That is why you see the full name before the metric is created, and why you withdraw a metric by deprecating it. The datatype is fixed for the same reason. The semantic id is not sent on the wire. It is a claim about what the metric means, so it can be corrected. So can the permitted values: a standard adds values between editions, and a schema keeps its own copy.

**A derived metric is arithmetic over stored readings.** Nothing is stored for it. Its definition is applied to the readings the inputs already have, so a changed definition would change every value it ever had. That is why a definition is fixed once saved.

**A time in state is resolved to the minute.** A state that lasts under a minute counts as a whole minute or not at all. It counts if it still holds when the minute ends. Over a day the result stays within a percentage point of the exact figure. A counter that resets and then climbs back past its old value inside one minute is counted short by that old value.

**Deprecated is not deleted.** A deprecated metric keeps its readings, and stays on the schemas that already model it. It is held back from the builder, so no new schema picks it up. The Deprecated Metrics tab lists deprecated metrics, each with the metric that replaced it. The tab is always there, and says so when nothing is deprecated.

**Uncatalogued is not unrecorded.** The readings of an uncatalogued metric are stored. But the metric has no description, unit or semantic id. No schema can model it, and an AAS export carries it without a semantic id. Catalogue it under the same name to fix all three. A name must match exactly, capital letters included: `temperature` and `Temperature` are two metrics.

**A group is part of the name.** `Axes/X/POSITION` belongs to the group `Axes` because of the text before the first slash, not because of a separate column. A name with no slash is listed under Ungrouped. A group typed with different capital letters from an existing one takes the existing spelling, so you do not get two groups.

## What this page is not

**It is not the Vocabulary page**, which holds the published standards themselves for you to read: MTConnect, ISO 22400, OPC UA and ASHRAE 223P. This page holds what this deployment has actually adopted from them. **It is not Schemas** either. A schema is a contract that names a selection of these metrics, and it has versions; a metric does not.
