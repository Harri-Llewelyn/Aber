Gateways need their own MQTT credential — the ACL confines each client to its own sparkplug_id
subtree, which only constrains anything if the username IS that id:

  node scripts/mosquitto-provision-gateway.mjs --target=k8s <gwy...>

DO NOT INSTALL WITH `--wait`. Helm blocks on workload readiness BEFORE it runs post-install hooks,
and those hooks are this chart's bootstrap: db-roles-init issues the passwords for `authenticator`,
`supabase_auth_admin` and `supabase_storage_admin`, which PostgREST, GoTrue, Realtime and
storage-api each wait for before starting. So `--wait` waits for pods that are waiting for the
hooks that `--wait` will not run until the pods are ready — reported, fifteen minutes later, as
`context deadline exceeded` with supabase-db perfectly healthy. Wait explicitly instead:

  for w in $(kubectl -n {{ .Release.Namespace }} get statefulset,deploy -o name); do
    kubectl -n {{ .Release.Namespace }} rollout status "$w" --timeout=10m
  done

(`--wait` on a later `helm upgrade` is fine — the roles already have their passwords.)

Check the migrations actually applied — the init hooks run AFTER the workloads are created, so a
`helm install` can return before they finish:

  kubectl -n {{ .Release.Namespace }} logs job/{{ include "acs-cymru.fullname" . }}-db-init
  kubectl -n {{ .Release.Namespace }} exec -it statefulset/supabase-db -- \
    psql -U postgres -d postgres -c '\dt public.*'

And that the historian's bootstrap ran (initdb scripts execute ONLY on an empty data directory, so
if these are missing the PVC must be destroyed, not the pod restarted):

  kubectl -n {{ .Release.Namespace }} exec -it statefulset/timescaledb -- \
    psql -U {{ .Values.timescaledb.username }} -d {{ .Values.timescaledb.database }} -c '\dt'
