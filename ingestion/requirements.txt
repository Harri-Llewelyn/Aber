# THE FORMAT IS THE POINT, not the library. Item 3 asks for "vendor-neutral Apache Parquet"

# Reading the cold archive back (`cold_archive query`).
#
# WHY NOT JUST pyarrow, WHICH IS ALREADY HERE. pyarrow reads a Parquet file; DuckDB queries a SET of
# them with SQL -- joins, aggregates, predicate pushdown and Hive partition awareness -- which is
# what "query in place" means as opposed to "load and filter in Python". The archive's layout was
# chosen for it: `year=YYYY/month=MM/` are columns to DuckDB, not directory names.
#
# It also keeps the archive honest about being VENDOR-NEUTRAL. The same query an operator runs here
# runs unchanged in the DuckDB CLI, in pandas, or in Power BI, against the same objects, with no
# ACS-Cymru component involved. That is the property Parquet was chosen for and this is what
# exercises it.
duckdb==1.1.3
# DuckDB needs this to hand TIMESTAMP WITH TIME ZONE values back to Python, and fails at fetch time
# without it -- "Required module 'pytz' failed to import" -- AFTER the query has already run. It is
# not listed as a hard dependency of duckdb because only the timezone-aware paths need it, and every
# row of `telemetry.time` is one.
#
# The alternative was casting `time` to text in the query, which would have removed a dependency by
# making the CSV output stringly-typed for every future consumer. Two hundred kilobytes is the
# cheaper side of that trade.
pytz==2024.2

# The S3 client cold telemetry is archived with (ingestion/cold_archive.py).
#
# THE PROTOCOL IS THE POINT, not the vendor. The same client reaches AWS, Cloudflare R2, Backblaze
# B2, Wasabi and a MinIO in another building, which is what lets the destination be the operator's
# decision and stay unknown to the code.
#
# WHAT IT IS USED FOR THAT A PLAIN HTTP PUT IS NOT: `ChecksumSHA256` on upload, which has the store
# validate the payload server-side and REJECT a corrupt write, and ranged GETs, which read a
# Parquet footer back without pulling the object across a metered link. Both are load-bearing --
# verification is what `--drop` keys the deletion of the only other copy on.
#
# Imported LAZILY, inside _s3_client(), so the ingestion daemon's own start-up path never pays for
# it. botocore comes with it and carries the retry and signing behaviour.
boto3==1.35.76

# Prometheus counters, histograms and the exposition format, for the /metrics endpoint.
#
# WHAT IT REPLACED. This daemon rendered the exposition itself -- a counter registry behind a lock,
# thirteen histogram buckets accumulated at render time, and the text format written by hand --
# on the argument that the format is a documented text protocol and rendering it was the smaller
# and more auditable half of what a library would do. The half that was not smaller was getting it
# right: cumulative `le` buckets in numeric and never lexical order, `+Inf` equal to `_count`,
# boundaries that render as 0.0025 and never 2.5e-03, one HELP/TYPE pair per family. Each of those
# is a silent wrongness rather than an error -- histogram_quantile() answers a malformed histogram
# with a plausible number -- and each had its own test. They are upstream's now.
#
# IT COSTS LESS THAN ANYTHING ALREADY HERE: pure Python, no transitive dependencies, ~150 KB. The
# `count("dropped_x")` call sites did not move and metrics.py still declares what each is published
# as, so the property that argument was protecting -- a counter beside the log line that explains
# it -- is untouched.
prometheus_client==0.26.0
